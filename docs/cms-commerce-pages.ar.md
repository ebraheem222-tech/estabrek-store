# تحرير Shop وCart من CMS

هذه المرحلة تضيف تصميم صفحات المتجر والسلة إلى المحرّر الحالي. المنتج والتصنيف والحساب والبحث وباقي المسارات الديناميكية لها المرحلة التالية في [الخطة الشاملة](superpowers/specs/2026-11-07-cms-platform-control-design.ar.md).

الحالة: نُشر الإصدار `b86b439` على `main`، وتحقق وصول أدوات اللوحة وكود الواجهتين وخدمة السيرفر الفعلية. فحصا الفرع و`main` نجحا على الشجرة نفسها.

## فتح التصميم

من «الصفحات ← تصميم صفحات المتجر» افتح Shop أوCart. إذا لم توجد صفحة مخصصة، «أنشئ تصميمًا قابلًا للتعديل» ينشئ **مسودة** بالعناصر الوظيفية اللازمة. فتح الصفحة من جلستين يعطي الصفحة نفسها؛ فتح صفحة موجودة يحافظ على تصميمها ومسودتها. لا ينشر هذا الزر الصفحة أو يفعّل استبدال تصميم الواجهة.

البطاقة تعرض حالة الصفحة وإعداد الاستبدال. إذا كان التصميم الافتراضي مفعلًا صراحةً، فعّل الصفحة المطلوبة من «الإعدادات ← صفحات CMS الأساسية» حتى يستخدم المتجر تصميم CMS المنشور. إيقاف الاستبدال يرجع للتصميم الافتراضي الموجود.

## العناصر المتاحة

| العنصر في «إضافة ← المتجر والسلة» | الوظيفة والتحكم |
|---|---|
| عرض المتجر | كتالوج حقيقي مع بحث وفلترة وترتيب وتصفح منتجات. يمكن تغيير عدد الأعمدة على الكمبيوتر والهاتف وإظهار البحث والفلاتر أو إخفائهما. |
| منتجات السلة | الصور والمنتجات وتغيير الكمية والإزالة، باستخدام السلة الموجودة. |
| ملخص الطلب | الإجمالي والخصم والكوبون والتوصيل المحسوبة من خدمات المتجر. |
| إتمام الطلب | معلومات العميل وطرق الطلب والدفع المفعلة في إعدادات النسخة. |

أجزاء السلة الثلاثة عناصر مستقلة في الشجرة. تستطيع نقلها بين الحاويات والأعمدة، وترتيبها وتغيير أبعادها وألوانها وخلفياتها وحواف SVG والحركة بالطريقة نفسها المستخدمة للعناصر الأخرى. محرك سلة واحد يربطها؛ تغيير كمية أو كوبون يحدّث الملخص المستخدم عند الطلب. تكوين العناصر لا يخزن سعرًا ثابتًا أو مفاتيح دفع أو بيانات عميل داخل مستند CMS.

داخل كل عنصر توجد واجهة تجارة وظيفية، وليست جميع أزرار الصف أو حقول النموذج عناصر شجرة منفصلة. تخصيص النصوص أو كل خلية داخل صف المنتج يمكن توسيعه لاحقًا؛ الحركة والتنسيق الحر يطبقان على العناصر الأربعة وحدودها الحالية.

## المعاينة والنشر

المحرّر يعرض منتجات وسلة تجريبية. البحث والفلاتر يعكسان توزيع المعاينة، وأزرار الشراء متوقفة. إطار Studio يعزل مخزن السلة ولا يستعيد جلسة حساب العميل. لا يقرأ سلة الزائر الحقيقية أو يغيّرها، ولا يحفظ طلبًا أو دفعة من معاينة العناصر الجديدة. تعديل الشكل أوSVG يحدث العرض في مستند الإطار نفسه.

نشر `/shop` يحتاج عنصر «عرض المتجر» واحدًا. نشر `/cart` يحتاج عنصرًا واحدًا من كل جزء: منتجات السلة والملخص وإتمام الطلب. يجب أن تبقى العناصر الأساسية ظاهرة على كل أحجام الشاشات، وخارج Popups ولوحات العرض المشروطة. يمكن حفظ قسم التجارة كبلوك مرتبط قابل لإعادة الاستخدام؛ فحص النشر يقرأ محتواه المنشور ضمن معاملة النشر نفسها، ويكشف العناصر المكررة بين البلوك وبقية الصفحة. العنصر المخفي أو المكرر يظهر بتنبيه واضح ولا يمكن تجاوز الفحص بـ«فرض النشر». مواعيد النشر والصلاحيات وتحديث الكاش تستخدم [دورة النشر السابقة](cms-page-publishing.ar.md).

التصاميم الأصلية والتصاميم القديمة المنشورة لا تستبدل تلقائيًا عند تثبيت التحديث. القوالب التجارية الجديدة، أو التصاميم التي أعيد نشرها بعد اجتياز الفحص، تحمل `root.props.commerceVersion: 1`. إذا صار أحدها ناقصًا عبر مسار كتابة أقدم مع بقاء العلامة، ترجع صفحة المتجر أوالسلة إلى واجهتها الافتراضية الوظيفية. التصاميم القديمة غير الموسومة تبقى كما هي حتى يراجعها المالك وينشرها من جديد.

## التشغيل والتحقق

لا توجد تبعيات أو ترحيلات قاعدة بيانات جديدة في هذه المرحلة. إنشاء المسودات يتطلب `pages:write` والنشر يتطلب `pages:publish`. تعديل إعداد الاستبدال يبقى في صفحة الإعدادات وبصلاحياتها الحالية.

التحقق يستخدم API معزولًا وPostgreSQL تجريبيًا في GitHub Actions ومتصفحًا محليًا. يشمل فتح المسودة بالتزامن، منع النشر الناقص، تطابق فحص الواجهة والسيرفر، البحث والترتيب، كمية السلة والكوبون وإرسال طلب تجريبي، الشحن والمخزون، التوافق مع التصميم القديم، وعزل السلة والحساب داخل Studio. لا تُنشأ صفحات أو طلبات اختبار على متجر التاجر المنشور.
