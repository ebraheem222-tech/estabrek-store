# تثبيت Estabrek لزبون مستقل

كل زبون يحصل على لوحة تحكم، واجهة متجر، Backend وقاعدة بيانات خاصة فيه. اسم المتجر واللوجو والثيم ومحتوى الصفحات إعدادات في قاعدة بيانات الزبون. Estabrek هو اسم المنتج؛ هوية الزبون هي اللي بتظهر على متجره.

## عناوين النسخة

مثال: `https://admin.example.com` للوحة، `https://shop.example.com` للمتجر، و`https://api.example.com` للسيرفر. استبدلها بعناوين الزبون الفعلية.

| الجزء | الإعداد | مثال |
|---|---|---|
| Admin / Vite | `VITE_API_BASE_URL` | `https://api.example.com/v1` |
| Admin / Vite | `VITE_STOREFRONT_BASE_URL` | `https://shop.example.com` |
| Storefront / Next.js | `API_BASE_URL` | `https://api.example.com/v1` |
| Storefront / Next.js | `NEXT_PUBLIC_API_BASE_URL` | `https://api.example.com/v1` |
| Storefront / Next.js | `NEXT_PUBLIC_SITE_URL` | `https://shop.example.com` |
| Storefront / Next.js | `ADMIN_ORIGIN` | `https://admin.example.com` |
| Backend | `DATABASE_URL` | اتصال PostgreSQL الخاص بالزبون |
| Backend | `JWT_SECRET` | مفتاح طويل وعشوائي خاص بهذه النسخة |
| Backend | `CORS_ORIGINS` | `https://admin.example.com,https://shop.example.com` |
| Backend | `STOREFRONT_URL` | `https://shop.example.com` |

إعدادات Vite و`NEXT_PUBLIC_*` تدخل في بناء ملفات الواجهة: تعديلها يتطلب إعادة البناء والتشغيل. `ADMIN_ORIGIN` لازم يكون مضبوط وقت بناء المتجر أيضاً حتى تسمح ترويسات الحماية بمعاينة القوالب داخل لوحة التحكم. تغيير العنوان ما بينقل قاعدة البيانات أو الملفات تلقائياً.

## إعداد المتجر بعد التثبيت

1. شغّل ترحيلات قاعدة البيانات من Backend بـ`npm run migrate:deploy`، واضبط حساب المالك وفق آلية نشر النسخة الحالية.
2. ابنِ وشغّل Backend، Storefront وAdmin بعناوين النسخة نفسها.
3. افتح إعداد المتجر من لوحة التحكم: اختَر نوع المتجر، ثم أي قالب من المكتبة أو صفحة فارغة، ثم اسم المتجر باللغات المطلوبة واللوجو.
4. اختَر قالباً لمعاينة الصفحة كاملة. فيه 1000 قالب ضمن 20 فئة، 50 لكل فئة، بتركيبات أقسام مختلفة. تستطيع اختيار قالب من أي مجال، وتحديد الفاتح أو الغامق. رسومات SVG المحلية محتوى أولي قابل للاستبدال بصور الزبون.
5. راجع الأقسام وأنواع المنتجات والقائمة والصفحة الرئيسية قبل التطبيق. المنتجات والأسعار التجريبية في المعاينة لا تُضاف إلى المخزون؛ الصفحة تستخدم كتالوج الزبون.
6. إذا عندك تصميم قائم، يلزم اختيار الاستبدال لتطبيق قالب كامل آخر. تُحفظ الرئيسية والهيدر والفوتر السابقة في السجل أولاً. المنتجات والتصنيفات الموجودة تبقى.
7. بعد التطبيق يفتح المحرّر مباشرة لتعديل العناصر والنصوص والصور وتوزيع الأقسام. استخدم تنقّل التصميم لفتح الرئيسية أو الهيدر أو الفوتر؛ النشر يجعل تعديل المنطقة المشتركة يظهر في كل صفحات المتجر. صفحة الثيمات تخصّص الألوان والخطوط والحواف.
8. القالب يصبح نسخة مستقلة من مستنداتك وإعدادات ثيمك، ولا يتغير بتعديل المصدر في مكتبة القوالب. زر اختيار قالب آخر من المحرّر يعيدك للإعداد. اختيار قالب جديد يستبدل التصميم، ولا يدمج تعديلاتك تلقائياً مع التصميم الجديد؛ النسخة السابقة تبقى في السجل.

النسخ الجديدة تستخدم وضع CMS الخاص بالزبون تلقائياً. لا تعدّل `ESTABREK_HOME_MODE` لتغيير تصميم زبون: التمييز محفوظ في `header.storeDesign.mode`. متاجر استبرق القديمة التي لا تحمل هذا الوسم تحتفظ بتصميمها الأصلي. لا يلزم ترحيل جديد لقاعدة البيانات لهذه الميزة.

## نقل السيرفر لاحقاً

خُذ نسخة من قاعدة البيانات والملفات، وانقلها للوجهة الجديدة، وثبّت نفس إصدار التطبيق وشغّل الترحيلات. احتفظ بمفاتيح التشفير الأصلية للبيانات المنقولة. بعدها عدّل عناوين API وStorefront وAdmin وأعد بناء الواجهات. جرّب تسجيل الدخول، رفع الصور، المعاينة والطلب على النسخة الجديدة قبل تحويل الدومين.

تعديل الاسم واللوجو والثيم يتم من لوحة التحكم. تغيير استضافة السيرفر يتم من إعدادات النشر؛ ما أضفنا زر داخل المتصفح يعدّل أسرار السيرفر أو ينقل البيانات.
