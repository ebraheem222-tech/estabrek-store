# خطة الباك-إند: استوديو بتتحكم منه بكلشي

**التاريخ:** 2026-11-12 · **الحالة:** خطة، ما انبنى منها شي لسا.

## الفكرة بسطر

قسم واحد بالأدمن اسمه «استوديو الباك-إند». منه بتبني جداول، علاقات، API، functions، تلقائيات، وميزات كاملة من قوالب جاهزة. كل شي فيه بيتعدّل، إله نسخ، وبيرجع بكبسة.

المرحلة B من الخطة الكبيرة (`cms-big-engine-plan.ar.md`) هي قلب هالخطة. هون رتّبتها وضفت حواليها اللي بيخلّيها بمستوى شركات: أساس، functions، قوالب، عمليات، وحوكمة.

## المبادئ

1. **كل شي بيانات، مش كود ثابت.** الجدول، العلاقة، الـ endpoint، الـ function، والقالب كلهم سجلات إلها شكل معروف، وبينفحصوا قبل الحفظ.
2. **مسودة ← فحص ← نشر.** ولكل شي نسخ، وفرق بين النسخ، ورجوع.
3. **الحماية عالسيرفر دايماً.** اللي بالمتجر ترتيب شكل بس.
4. **جداول المتجر الأساسية محمية.** بتنقرأ وبتنربط. الكتابة عليها بس عبر أوامر معروفة (مثل «اعمل كوبون» أو «عدّل مخزون»).
5. **ما في كود بيشتغل بدون قفص وحدود:** وقت، ذاكرة، وشبكة.
6. **كل تشغيل بينسجّل:** مين، شو، إيمتا، قديش أخد، وشو صار.
7. **نفس الجملة بكل مكان:** «لما ← مين ← إذا ← اعمل ← وإلا ← إذا فشل»، للصفحات وللسيرفر.

## المراحل

لكل مرحلة: **بتحصل على** (اللي بتشوفه إنت)، **بينبني** (الشغل الهندسي)، و**خلصت لما** (كيف منعرف إنها خلصت).

### E0. الأساس

**E0.1 مراقبة النشر** (صغيرة، وأول شي)
- بتحصل على: صفحة «حالة السيرفر» بتقول أي نسخة حية وهل هي آخر نسخة. وتنبيه بالجرس وبالإيميل إذا نشر فشل أو تأخّر.
- بينبني: السيرفر بيعلن نسخته (`/health` مع رقم الـ commit). مهمة بتقارنها بآخر commit على main. حدث جديد للتلقائيات: «النشر فشل».
- خلصت لما: نشر فاشل بيوصلك تنبيهه خلال 10 دقايق.
- **انبنت (2026-11-13):** صفحة «حالة السيرفر» بالأدمن (`/admin/system/server`). السيرفر بياخد رقم تعديله من Railway لحاله، ومهمة `deployWatch` بتسأل GitHub كل دقيقة (بدون مفتاح، المستودع عام). تعديل ما صار حي بعد 10 دقايق، أو Railway علّم نشره فاشل، بيرن الجرس لحاله وبيوصل للتلقائيات كحدث «النشر ما صار حي» (إيميل بكبسة من الصفحة). `/health` صار يقول رقم التعديل. الكود: `lib/deployWatch.ts`.

**E0.2 سجل تشغيل دائم**
- بتحصل على: صفحة وحدة فيها كل تشغيل: مهمة، تلقائية، function، webhook. مع الوقت والمدة والنتيجة والخطأ.
- بينبني: جدول `Run` واحد بدل الذاكرة. تنظيف تلقائي للقديم.
- خلصت لما: إعادة تشغيل السيرفر ما بتمسح السجل.

**E0.3 صف انتظار دائم**
- بتحصل على: شغل الخلفية ما بيضيع. اللي بيفشل بينعاد لحاله، واللي بيفشل كتير بيروح لقائمة «بدها نظر».
- بينبني: صف على Postgres (جدول، وقفل `SKIP LOCKED`). إعادة محاولة بتأخير متزايد. مفتاح «مرة وحدة بس» (idempotency). المهام الحالية بتنتقل عليه.
- خلصت لما: مهمة انقطعت بنص شغلها بتكمّل بعد إعادة التشغيل، ومرة وحدة بس.

**E0.4 نسخ موحّدة**
- بتحصل على: لكل جدول، function، و endpoint: قائمة نسخ، فرق بين أي نسختين، ورجوع.
- بينبني: نموذج نسخ واحد لكائنات الاستوديو، وبينضاف لـ «السجل» الموجود.

**E0.5 صلاحيات أدق**
- بتحصل على: دور بيشوف جدول وما بيعدّله، أو ما بيشوف حقل معيّن، أو بيشوف سجلاته بس.
- بينبني: صلاحيات بالشكل `data:<جدول>:read|write`، `functions:run`، `api:keys`. وقواعد صف (المالك، الدور، شرط على حقل).

### B1. الجداول

- بتحصل على:
  - شبكة متل Airtable: فلترة، ترتيب، بحث، صفحات، تعديل بالخلية، وتعديل جماعي.
  - استيراد وتصدير CSV و Excel، مع معاينة قبل الاستيراد وتقرير بالأسطر المرفوضة.
  - مسودة ومنشور لكل سجل. سلة محذوفات بترجّع منها.
  - جداول المتجر (منتجات، طلبات، زبائن، تصنيفات) بتبين بنفس الشبكة، للعرض بس.
- بينبني: الشبكة فوق «المجموعات» الموجودة (ما منبدأ من صفر). فهرسة تلقائية للحقول اللي بتنفلتر كتير. رفع الحد من 2000 عنصر.
- خلصت لما: جدول فيه 50 ألف سجل بينفتح وبيتفلتر بأقل من ثانية.

### B2. الـ schema

- بتحصل على:
  - أنواع حقول أكتر: نص غني، عملة، تاريخ ووقت، إيميل، تلفون، ملف، فيديو، موديل 3D، JSON، اختيار متعدد، موقع، حقل محسوب، slug تلقائي.
  - قواعد لكل حقل: إجباري، فريد، قيمة افتراضية، حدود، نمط. ورسالة الخطأ بالعربي والعبري والإنجليزي.
  - لما تغيّر نوع حقل: معاينة كيف رح تتحوّل البيانات، وكم سجل ما بيتحوّل، قبل ما تطبّق.
  - كل تغيير بالـ schema إله نسخة وبترجع عنه.
- خلصت لما: تغيير نوع حقل على جدول فيه بيانات ما بيضيّع ولا قيمة بدون ما يقلّك قبل.

### B3. العلاقات

- بتحصل على:
  - واحد-لواحد، واحد-لكثير، كثير-لكثير. بين جداولك، وبين جداولك وجداول المتجر.
  - مخطط بصري: بتسحب خط بين جدولين لتعمل علاقة.
  - عند الحذف بتختار: بينحذف معه، بينفك الربط، أو بينمنع.
  - بالشبكة بتختار السجلات المرتبطة من نافذة بحث. وحقول «تجميع» (عدد، مجموع، آخر تاريخ) من المرتبط.
- بينبني: جدول روابط واحد مفهرس بالاتجاهين.
- خلصت لما: حذف سجل مربوط بيتصرّف متل ما اخترت، وما بيترك روابط يتيمة.

### B4. API تلقائي

- بتحصل على:
  - لكل جدول: قائمة (فلترة، ترتيب، صفحات، جلب المرتبط)، سجل واحد، إضافة، تعديل، حذف.
  - صلاحية لكل جدول ولكل عملية: عام، زبون (سجلاته بس)، موظف بدور، أو مفتاح API.
  - مفاتيح API: بتنعمل وبتنلغى من الأدمن، كل مفتاح بصلاحياته وحدّه. المفتاح بيبين مرة وحدة بس.
  - حد للطلبات لكل مفتاح ولكل IP.
  - وثائق OpenAPI تلقائية، صفحة بتجرّب فيها الطلبات، وأنواع TypeScript جاهزة للنسخ.
- بينبني: التحقق zod بينبني من الـ schema نفسه. كل جدول بيبلّش «خاص» لحد ما تفتحه.
- خلصت لما: جدول جديد بيصير إله API موثّق ومحمي بدون ولا سطر كود.

### F. الـ Functions (هون B5 و D2 بيصيروا شي واحد)

**F1. محرك الخطوات عالسيرفر**
- بتحصل على: function بتبنيها بخطوات، بنفس جملة المشغّلات.
- الخطوات:
  - بيانات: دوّر، جيب، أضف، عدّل، احذف (على جداولك).
  - المتجر: أوامر معروفة (اعمل كوبون، عدّل مخزون، ضيف ملاحظة لطلب، علّم زبون).
  - تحكّم: شرط، حلقة، مع بعض، استنّى، نادي function تانية.
  - برّا: طلب HTTP لمواقع مسموحة، إيميل، واتساب، SMS (عبر الـ outbox الموجود).
  - الرد: شو بيرجع للّي نادى.

**F2. كود بقفص**
- بتحصل على: خطوة «كود» بتكتب فيها JavaScript لما الخطوات ما بتكفي.
- بينبني: الكود بيشتغل جوّا QuickJS داخل WebAssembly، مش جوّا السيرفر نفسه. إله أدوات محدّدة بس: `db`، `http`، `secrets`، `log`، `send`.
- الحدود: ثانيتين، 32 ميغا ذاكرة، بدون ملفات، وبدون شبكة إلا عبر `http` لمواقع مسموحة.

**F3. شو بيشغّلها**
- endpoint خاص: مسار، method، مدخلات بقواعد تحقق، وصلاحية.
- نداء من صفحة: خطوة «شغّل function» بالمشغّلات. هاد هو D2، ومعه: تطبيق كوبون، و«مين مسموحله» بينفحص عالسيرفر (اشترى منتج، دور موظف).
- حدث بيانات: سجل انضاف، تعدّل، أو انحذف.
- حدث متجر: طلب جديد، دفع، شحن، مخزون قليل، زبون جديد، سلة متروكة.
- جدول زمني: كل ساعة، كل يوم، أو تعبير cron.
- webhook داخل: عنوان خاص مع توقيع.

**F4. التجربة والاختبار**
- مدخلات تجريبية محفوظة مع كل function.
- تشغيل جاف: بيقلّك شو كان رح يتغيّر، وما بيغيّر شي.
- خطوة خطوة: بتشوف قيمة كل متغيّر بعد كل خطوة.
- اختبارات بتشتغل لحالها قبل كل نشر. إذا وقعت، النشر بيوقف.

**F5. الأسرار والاتصالات**
- خزنة: مفاتيح الخدمات الخارجية مشفّرة. بتنكتب وما بتنقرأ بعدها.
- اتصالات جاهزة: Google Sheets، Telegram، Slack، ERP عبر HTTP. بتختار الاتصال بدل ما تكتب المفتاح بكل function.

**F6. webhooks طالعة**
- بتختار الأحداث والعنوان. كل طلب موقّع (HMAC). اللي بيفشل بينعاد، وبتشوف سجل التسليم.

- خلصت F لما: function بتنبني، بتنجرّب، بتنشر، بتشتغل من 6 أنواع مشغّلات، وكل تشغيل إله سجل. وكود سيّء (حلقة ما بتخلص) بينقتل لحاله وما بيأثر عالمتجر.

### T. القوالب

**قوالب functions** (خطوات جاهزة بتعدّلها):
- طلب جديد ← واتساب لصاحب المتجر.
- دفع ← نقاط ولاء للزبون.
- مخزون قليل ← إيميل للمورّد.
- سلة متروكة ← تذكير بعد ساعتين.
- تسليم ← طلب تقييم بعد 3 أيام.
- سجل جديد ← سطر بـ Google Sheets.
- كوبون لمرة وحدة لكل زبون.
- webhook من شركة الشحن ← تحديث حالة الطلب.

**قوالب ميزات** (حزمة: جداول + علاقات + functions + endpoints + صفحات أدمن + عناصر للصفحات):

| القالب | شو فيه |
|---|---|
| نقاط الولاء | رصيد لكل زبون، قواعد كسب وصرف، صفحة «نقاطي». |
| الحجوزات | مواعيد، أوقات متاحة، تأكيد وتذكير. |
| قائمة الانتظار | تسجيل على منتج، وإشعار لما يرجع. |
| بطاقات الهدايا | أكواد برصيد، صرف جزئي. |
| المرتجعات | طلب إرجاع، أسباب، حالات، موافقة. |
| أسعار الجملة | قوائم أسعار لمجموعات زبائن. |
| برنامج الإحالة | رابط لكل زبون، ومكافأة للطرفين. |
| تذاكر الدعم | تذكرة، ردود، حالات، تقييم. |
| الفروع | فروع، ساعات دوام، خريطة. |
| المدونة والأسئلة | موجودين كمجموعات، بيصيروا قوالب. |

- بتحصل على: معرض قوالب. بتشوف شو رح ينضاف قبل التثبيت. بعد التثبيت كل شي بيتعدّل. وإزالة نظيفة.
- بينبني: صيغة واحدة للقالب (ملف manifest بنسخة). تثبيت كمسودة، ترقية بتحافظ على تعديلاتك، وإزالة بتسأل عن البيانات.
- خلصت لما: قالب بيتثبّت، بيتعدّل، بيترقّى، وبينشال بدون ما يترك أثر.

### B6. الربط بالصفحات

- أي عنصر بالصفحة بيقرأ من جدول أو من علاقة (قائمة، تفاصيل، عدّاد).
- فورم بتبنيه بالمحرر: كل حقل بقواعده، وبيكتب على جدول بنفس التحقق اللي بالـ API.
- أحداث جديدة للمشغّلات: «إرسال فورم» و«تغيّر قيمة».
- حماية من السبام: حد للطلبات، وحقل مخفي للروبوتات.

### O. مركز العمليات

- **سجل التشغيل:** فلترة حسب function، حالة، ووقت. وإعادة تشغيل اللي فشل.
- **الأخطاء:** مجمّعة حسب النوع، مع أول وآخر مرة.
- **التنبيهات:** function بتفشل كتير، صف واقف، حصة قرّبت تخلص، نشر فشل.
- **الحصص:** حد يومي لكل function، لكل مفتاح، وللطلبات الخارجية.
- **النسخ الاحتياطي:** تجربة استرجاع شهرية تلقائية على قاعدة مؤقتة، وتقرير بنتيجتها.
- **البيانات الشخصية:** تصدير كل بيانات زبون، وحذفها عند الطلب.
- **زر الطوارئ:** وقّف كل الـ functions، أو function وحدة، فوراً.

### G. الحوكمة

- **بيئة تجربة:** نسخة من القاعدة (فرع على Neon) بتجرّب عليها تغيير الـ schema قبل الحي.
- **موافقات:** تغيير حسّاس (حذف جدول، فتح جدول للعام، نشر function بتكتب على المتجر) بده موافقة شخص تاني. اختياري.
- **سجل التغييرات:** مين نشر شو، مع الفرق.
- **رجوع شامل:** رجّع الاستوديو كله لحالته بتاريخ معيّن.

### A. المساعد

- بتوصف بالكلام («بدي نقاط ولاء: نقطة لكل 10 شيكل»)، وهو بيقترح جداول وخطوات.
- الاقتراح بيبين كفرق، وما بينحفظ إلا لما توافق.
- مبني على قسم الذكاء الاصطناعي الموجود، ومطفي لحد ما تشغّله.

| وين بتنخزن جداولك | JSONB متل المجموعات، مع جدول روابط وفهارس تلقائية. | ما في migration لكل زبون، وما في خطر على جداول المتجر. اللي صار اليوم بالـ migrations سبب كافي. |
| إذا جدول كبر كتير | خيار «ترقية» لجدول Postgres حقيقي، بعدين. | ما منحتاجه قبل 100 ألف سجل بجدول واحد. |
| كيف بيشتغل الكود | QuickJS داخل WebAssembly. | `vm` تبع Node مش قفص حقيقي. `isolated-vm` بده بناء native، وهاد بيعقّد النشر على Railway. |
| صف الانتظار | على Postgres. | ما بده خدمة جديدة، وبيدخل بالنسخ الاحتياطي. Redis موجود بس اختياري عندك. |
| شكل الـ API | REST مع OpenAPI. | أبسط للربط مع أي نظام. GraphQL بعدين إذا لزم. |
| جداول المتجر | قراءة وربط، والكتابة عبر أوامر. | غلطة بـ function ما لازم تخرّب طلب أو مخزون. |
| القوالب | ملفات manifest جوّا الكود، بنسخ. | بتنفحص بالاختبارات، وبتنتقل لكل نسخة زبون مع النشر. |

## شو مش رح نعمل

- مكتبات npm جوّا الـ functions. الأدوات المحدّدة بس.
- SQL مباشر من الاستوديو.
- تعديل شكل جداول المتجر الأساسية من الاستوديو.
- function بتشتغل أكتر من ثواني. الشغل الطويل بينقسم لمهام بالصف.

## المخاطر وكيف منسكّرها

| الخطر | الحل |
|---|---|
| function بتاكل السيرفر | حدود وقت وذاكرة، حصة يومية، وزر طوارئ. |
| تغيير schema بيضيّع بيانات | معاينة قبل التطبيق، نسخة قبل كل تغيير، ورجوع. |
| API بيسرّب بيانات | كل جدول خاص من الأول، وفتحه للعام بده تأكيد. |
| function بتبعت أسرار لبرّا | الأسرار ما بتنقرأ من الكود، بتنحط بالطلب عالسيرفر بس، والمواقع المسموحة محدّدة. |
| سيرفر واحد على Railway | الصف بيشتغل جوّاه هلأ. لما الضغط يكبر، خدمة worker لحالها بنفس الكود. |
| نشر بيفشل وما حدا بيعرف | E0.1، وهي أول خطوة. |
