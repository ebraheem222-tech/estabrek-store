**التاريخ:** 2026-11-21 · **الحالة:** خطة. انبنى منها: الموجة 0 كلها (#230، #232، #233، #234، #235، 2026-11-22)، والموجة 1 كلها: إعدادات الموقع (#236)، لوحته بكل قطعها (#237، #238)، والمالك بيرتّبها (#239). ومن الموجة G: الأولى (G1، #240) والتانية (G2، #241 و#242). طلبها المالك اليوم: «صمّم حوالي 300 موقع من كل الأنواع، وكل موقع بيختار الثيم المناسب إله، مع حقول مناسبة، ومنطق، وميزات، وتحكّمات خاصة فيه بلوحة التحكم… حتى لو كان موقع تواصل اجتماعي». كل موجة بينبني منها شي بينحط عليها سطر «انبنى» بتاريخه.

هاي الخطة بتكمّل على خطّتين موجودات وما بتبدّلهم:
- `fullstack-platform-plan.ar.md`، المرحلة 4 (القوالب): منها الصيغة `.feature.json` والـ 12 موقع الأولانيين (#177).
- مكتبة الأقسام (Section DNA، #213 لـ #226): منها شكل الصفحات.

**إضافة 2026-11-22:** المالك طلب كمان مواقع لسيرفرات الألعاب (FiveM، ماينكرافت، وسيرفرات ألعاب تانية). إلها قسم «سيرفرات الألعاب بالتفصيل»، والنموذج 14 «سيرفر»، والمجال 21 (20 موقع)، والموجة G. هيك صاروا 320 موقع.

## الفكرة بسطر

المالك بيختار **نوع موقع** (مطعم، عيادة، مدرسة، سوق بائعين، شبكة تواصل…) وبياخد **موقع كامل شغّال**: صفحات مصمّمة بثيم بيناسبه، جداول بحقول بتناسبه، منطق شغّال (حجز، دفع، متابعة، موافقة…)، **ولوحة تحكّم خاصة فيه** بالأدمن. وكل شي فيه بيتعدّل بعدين بالمحرر.

## الموقع من عيون المالك (كيف رح يشتغل)

1. **شو نوع موقعك؟** بيختار مجال (21 مجال) ← نوع (15 بكل مجال) ← بيشوف المعاينة الكاملة.
2. **اختار الشكل:** بيطلعله أنسب 6 ثيمات لهاد النوع، كل واحد معاين **على موقعه هو** (مش على متجر). وفي «كل الثيمات» إذا بدّه.
3. **عنّك:** الاسم، اللوغو، الألوان (من اللوغو)، التلفون، العنوان، ساعات الدوام، اللغات.
4. **شو بدّك يشتغل؟** الوحدات كبسات: «حجز أونلاين ✓»، «دفع مسبق ✗»، «مدوّنة ✓»، «رسائل خاصة بين الأعضاء ✓»… كل كبسة بتقول شو بتضيف.
5. **تثبيت كمسودة:** الجداول بسطور جاهزة، الصفحات، المنطق، واللوحة. ولا شي بيبيّن للناس لسّا.
6. **جرّب وانشر:** معاينة، فحص تلقائي («كل شي تمام» أو شو الناقص)، «خلّيه الرئيسية»، نشر.

بعدها بيلاقي بقائمة الأدمن **مجموعة باسم موقعه** فيها لوحته: طلبات اليوم، تقويم الحجوزات، طابور الموافقة، الأعضاء، الإعدادات… حسب نوع الموقع.

ونفس الخطوات بتصير خطوة بـ «نسخ الزباين» (#191–#198): نسخة زبون جديدة بتطلع من أول يوم بموقعها.

## المحرّك: الموقع = مخطّط من وحدات

بدل ما نكتب 300 موقع باليد، منبني **وحدات** (حوالي 80) وكل موقع **مخطّط** بيركّبهم.

- **الوحدة (module):** قطعة كاملة لحالها: جداولها وحقولها وعلاقاتها، مين بيقرأ ومين بيكتب، functions ومشغّلاتها، أقسام وصفحات، قطع للوحة، إعدادات، سطور جاهزة، واختبارات. مثال: «منشورات»، «متابعة»، «مواعيد»، «اشتراك شهري».
- **المخطّط (blueprint):** الموقع = قائمة وحدات بخياراتها + حزمة كلام وصور بتلات لغات + ثيمات بتناسبه + أدوار + شكل الصفحة الأولى + لوحته.
- **النموذج (archetype):** 14 نموذج بيعطوا كل مخطّط بدايته (تحت). الموقع بيبلّش من نموذج وبيزيد عليه.
- **الملف:** صيغة جديدة `estabrek.site` (نسخة 2) فوق `estabrek.feature`. بتتحوّل لنفس الجداول والـ functions والصفحات، فالتثبيت والإزالة والترقية (#174، #176) بيضلّوا شغّالين. والإضافات: `modules`، `settings`، `panel`، `themes`، `roles`، `nav`.

شكله تقريباً:

```text
{
  format: "estabrek.site", formatVersion: 2,
  key: "site-neighbourhood", version: "1.0.0",
  field: "social", archetype: "social",
  modules: [
    { use: "profiles" },
    { use: "posts", with: { media: ["photo", "video"], approval: "new-members" } },
    { use: "follow" }, { use: "comments" }, { use: "reactions" },
    { use: "groups" }, { use: "messages" }, { use: "reports" }, { use: "directory" }
  ],
  settings: [ { key: "newMemberDays", kind: "number", default: 7, public: false, label: {ar, en, he} }, … ],
  panel:    [ { page: "moderation", widgets: [ { queue: "reports" }, { queue: "posts:waiting" } ] }, … ],
  themes:   { fit: { field: "social", moods: ["warm", "calm"], ui: "app" } },
  pack:     { biz: {…}, words: {…}, rows: {…} }
}
```

الـ 12 موقع الموجودين بيتحوّلوا أول شي لمخطّطات (نسخة 2.0.0)، وبيطلع منهم **نفس** الملف تقريباً: هيك منعرف إنّه المحرّك صح، ومين ثبّتهم بيترقّى بدون ما يخسر تعديلاته.

## الوحدات (حوالي 80)

**أ. أساس (كل موقع):** صفحات الموقع وقائمته وذيله، «خلّيه الرئيسية»، رسائل التواصل، أسئلة، آراء، أخبار/مدونة، فروع وخريطة، فريق، ألبوم، صفحات الخصوصية والشروط، SEO وصور المشاركة، نشرة بريدية، زر واتساب، إمكانية وصول، بحث بالموقع، لغات الموقع.

**ب. عرض:** قائمة رئيسية (منيو/خدمات/غرف…)، صفحة عنصر، فلاتر وبحث، مقارنة، ألبوم أعمال، قبل وبعد، مخطط تفاعلي (شقق، أجنحة)، حاسبات (سعر، قسط، سعرات).

**ج. حجز ومواعيد:** طاقم وجداولهم، خدمات بمدة وسعر، **محرّك الفترات** (دوام، عطل، فواصل، سعة، أول موعد فاضي)، موارد (غرفة، ملعب، سيارة)، حصص بسعة وقائمة انتظار، ليالي (فندق/شاليه)، دور حيّ (طابور)، تذكيرات، إلغاء وتأجيل بقواعد، دفعة تثبيت، باقات جلسات بعدّاد، إقرار وموافقة.

**د. طلب:** الطلب من كتالوج المتجر نفسه (مش سلة جديدة)، استلام بساعة، مناطق توصيل وسعرها، شاشة تحضير بأعمدة، طلب بالوزن/بالتصميم، طلبات متكررة، QR طاولة.

**هـ. عضوية:** خطط وأسعار، **اشتراك شهري متكرر**، محتوى للأعضاء بس، بطاقة عضو QR وتسجيل دخول للمكان، نقاط وولاء، إحالات، قائمة انتظار.

**و. تواصل اجتماعي:** بروفايل عام باسم مستخدم، متابعة/صداقة، منشورات (نص، صور، فيديو)، الصفحة الرئيسية للمنشورات (feed)، تفاعلات، تعليقات بردود، ذكر @ ووسوم #، مجموعات، فعاليات المجتمع، رسائل خاصة وجماعية (حيّة)، مركز إشعارات، قصص 24 ساعة، استطلاعات، حفظ، حظر وكتم، بلاغات وإشراف، شارة تحقّق، الرائج، دعوات بكود، نقاط وشارات وسمعة.

**ز. سوق:** بائعين بيسجّلوا وبيستنّوا موافقة، إعلانات بموافقة وانتهاء، عروض ومفاوضة، مزاد بعدّاد وقت حيّ، عمولة ودفتر مستحقّات، نزاعات، تقييم البائع، مفضّلة، تنبيه بحث محفوظ، وظائف وطلبات توظيف بسيرة ذاتية.

**ح. تعليم:** كورسات ودروس (فيديو/نص/ملف)، تسجيل، تقدّم، بنك أسئلة واختبارات بوقت وتصحيح تلقائي، تسليم واجبات، شهادات PDF، صفوف وجدول حصص، حضور، دفتر علامات، **بوابة أهل**.

**ط. إعلام:** مقالات بكتّاب وتصنيفات ووسوم، مراجعة قبل النشر (كاتب ← محرّر)، نشر بموعد، شريط عاجل، تعليقات، حلقات صوت و RSS، مكتبة فيديو، محتوى مدفوع بعدد مقالات، ويكي بنسخ.

**ي. خير ومجتمع:** حملات بهدف وشريط تقدّم، تبرع لمرة أو شهري، كفالة بتقارير، متطوعين ومناوبات، عرائض وتصويت، اشتراكات أعضاء.

**ك. فعاليات:** فعاليات وجدول ومتحدثين، تذاكر بأنواع، مقاعد بمخطّط، تأكيد حضور (RSVP)، QR وصفحة ماسح بكاميرا التلفون، ألبوم من الحضور.

**ل. شغل:** خط مبيعات (كانبان)، عروض أسعار بتنحسب لحالها، فواتير، تذاكر دعم بوقت ردّ (SLA)، مهام ومشاريع، طلبات إجازة، مخزون، توصيل وسائقين، تتبّع برقم، بوابة زبون بمستنداته الخاصة، طلبات بمراحل (معاملة، تأشيرة، شكوى).

## لوحة الموقع (التحكّمات الخاصة بكل موقع)

**الجديد:** لما يتثبّت موقع، بتطلع بقائمة الأدمن مجموعة باسمه. صفحاتها مبنية من **قطع لوحة** عامة، بتقرأ من جداول الموقع وبتشغّل functions تبعه. القطع:

| القطعة | شو بتعمل | مثال |
|---|---|---|
| **أرقام** | عدّ/مجموع بفلتر، ومقارنة مع الأسبوع الماضي | حجوزات اليوم، أعضاء جدد، تبرعات الشهر |
| **رسم** | منحنى أو أعمدة بالوقت | طلبات بالساعة، نمو الأعضاء |
| **طابور** | سطور بتستنّى قرار، وكبسات قرار بتشغّل function | منشورات للموافقة، بائعين جدد، بلاغات |
| **كانبان** | أعمدة حسب الحالة، سحب بين الأعمدة | طلبات المطبخ، تذاكر الدعم، عملاء محتملين |
| **تقويم** | يوم/أسبوع/شهر، سحب لتغيير الموعد | المواعيد، الحصص، الليالي، الفعاليات |
| **جدول محفوظ** | منظر من شبكة الجداول بفلتره وأعمدته | «طلاب صف تاسع»، «إعلانات خلصت» |
| **خريطة** | سطور بموقع | الفروع، السائقين، الإدراجات |
| **صفحة شخص** | كل شي عن عضو/زبون/مريض بمكان واحد + إجراءات | منشوراته، حجوزاته، دفعاته، ملاحظات، حظر |
| **إعدادات** | فورم من إعدادات الموقع | «الحجز مفتوح»، «عمولة 8%»، «ساعات الدوام» |
| **إجراءات سريعة** | كبسة بتشغّل function | «سكّر الحجز اليوم»، «ابعت إعلان لكل الأعضاء» |
| **تقرير** | جدول وأرقام بفترة، وتصدير Excel/CSV | مبيعات البائعين، حضور الشهر |
| **ماسح** | كاميرا التلفون بتقرأ QR | دخول النادي، تذاكر الحفلة |

- كل قطعة بتحترم صلاحيات الموظف (الميزة والجدول)، وبتلات لغات، وبتشتغل عالتلفون.
- المالك بيقدر يرتّب لوحته، يزيد قطعة أو يشيلها (نفس فكرة «شو بدّك يشتغل»).

### إعدادات الموقع

كل مخطّط بيعلن إعداداته (كبسة، رقم، نص، اختيار، ساعات دوام، لون، مناطق). بتنحفظ مع الميزة، وبتنقرأ:
- بالمنطق: `{{settings.newMemberDays}}` بأي خطوة.
- بالصفحات: نص مربوط بإعداد (ساعات الدوام)، وقسم بيبيّن أو بيختفي حسب كبسة («الحجز مفتوح»).
- **الإعداد العام بس بيوصل للمتجر**. الخاص (العمولة، حدود الإشراف) ما بيطلع من السيرفر.

أمثلة: المطعم (ساعات، عطل، «خلص اليوم»، مناطق التوصيل وأسعارها، أقل طلب، وقت التحضير)، العيادة (مدة الموعد، كم يوم لقدّام، قبل قدّيش الإلغاء، نص التذكير)، الشبكة (مين بينشر، موافقة أول كم يوم، حد المنشورات بالساعة، الرسائل لمين، كلمات ممنوعة، كم بلاغ بيخبّي منشور)، السوق (العمولة، موافقة البائعين، مدّة الإعلان)، المدرسة (الفصول، سلّم العلامات، مين من الأهل بيشوف شو).

## الثيم المناسب لكل موقع

1. **علامات لكل ثيم:** المجالات اللي بيناسبها، المزاج (هادي، جريء، فخم، مرِح، رسمي، دافي، تقني)، الكثافة (مرتاح/عادي/كثيف)، الصور (أساسية/شوي/بلاها)، والواجهة (موقع/تطبيق).
2. **كل مخطّط بيعلن شو بدّه:** المجال والمزاج والحاجات (مثلاً الشبكة بدها «تطبيق» وكثافة عادية، الأخبار كثيفة، المصوّر صور أساسية).
3. **ترتيب بالنقاط:** المجال + المزاج + الحاجات. أعلى 6 بيطلعوا بمعالج التثبيت، معاينين على الموقع نفسه.
4. **12 عيلة جديدة للمواقع**، 4 ثيمات بكل وحدة = **48 ثيم جديد** (المجموع ~126): طبّي (هادي ونظيف)، قانون ومال (رسمي)، تعليم (ودود)، **مجتمع وتواصل (شكل تطبيق)**، إعلام وأخبار (تحريري كثيف)، خيري (دافي وإنساني)، شركات و SaaS (تقني نظيف)، مناسبات (احتفالي)، سفر (صور أوّلاً)، صناعة وخدمات (متين)، بلدي وحكومي (وضوح وتباين عالي)، ترفيه (جريء ومرِح).
5. **قطع التطبيق بتلبس الثيم:** بطاقة منشور، كاتب منشور، خيط تعليقات، فقاعات محادثة، رأس بروفايل، اختيار موعد، خطوات حجز، قائمة دروس وتقدّم، تذكرة QR، عدّاد تبرعات، شريط عاجل… حوالي 25 قطعة × 3–4 تصاميم، كلها من ألوان وخطوط الثيم.
6. **أقسام بنفس الروح:** كل ثيم إله «لوكات» DNA بتناسبه، فالأقسام اللي بتنزل بالصفحات بتطلع من نفس العيلة. وكبسة «شكل تاني» بتبدّل التركيب وبتخلّي الكلام.
7. **القاعدة نفسها:** كل تصميم أصلي من عنّا، ما في نسخ عن مواقع تانية، وتصميم إستبرق (الوردي) ما بينحط لمواقع تانية.

## شبكة التواصل بالتفصيل

لأنها أصعب نوع، ولأن المالك سمّاها بالإسم.

**الصفحات:** الرئيسية (منشورات اللي بتابعهم + الجديد + الرائج)، `/u/<اسم>` البروفايل، صفحة المنشور، المجموعات وصفحة كل مجموعة، الرسائل، الإشعارات، استكشاف (وسوم ورائج وأشخاص)، إعدادات حسابي وخصوصيته، الانضمام مع قواعد المجتمع.

**لوحتها:** طابور الإشراف (منشورات بتستنّى، بلاغات بأسبابها، إخفاء/حذف/تنبيه/حظر بكبسة)، الأعضاء (بحث، شارة تحقّق، مشرف، حظر لمدّة)، أرقام (أعضاء جدد، نشطين باليوم، منشورات، بلاغات)، كلمات ممنوعة، إعلان مثبّت للكل مع push، والإعدادات (مين بينشر: الكل/بعد موافقة/المتحقّقين، موافقة لأول كم يوم، حد بالساعة، الرسائل: الكل/المتابَعين/مسكّرة، مين بيعمل مجموعة، فيديو، قصص، عمر أدنى، دخول بدعوة).

**اللي لازم ينضاف للمحرّك (موجة 4):**
1. عدّاد بيزيد وبينقص بخطوة وحدة بأمان (اليوم «صوّت» بيقرأ وبيكتب، وطلبين مع بعض بيضيّعوا صوت).
2. «مرّة لكل شخص» على حقلين مع بعض (تفاعل واحد لكل منشور).
3. فهارس لحقول بيعلنها المخطّط (المؤلّف، المجموعة، التاريخ)، لأن السطور JSON بجدول واحد.
4. استعلام «منشورات اللي بتابعهم» وتصفّح لانهائي بمؤشّر بدل الصفحات.
5. حقل «ناس كتير» (أعضاء محادثة أو مجموعة) بيعطيهم حق القراءة، متل حقل «زبون» بس لأكتر من واحد.
6. بروفايل عام لكل زبون باسم مستخدم (صفحة لكل شخص).
7. فيديو من الزباين (اليوم الملفات صور و PDF ومستندات وصوت بس) مع تحويل للبث.
8. حدود كتابة لكل جدول ولكل زبون بالساعة، من الإعدادات.
9. سطور بتنتهي لحالها (القصص) وشغل كل ساعة (الرائج).
10. فحص محتوى اختياري بالذكاء المحلي (خطة `local-ai-plan.ar.md`): كلام مسيء، صور.

**بصراحة عن الحجم:** هاد بيكفي لمجتمع لحد عشرات آلاف الأعضاء ومليون منشور تقريباً على نسخة وحدة. أكبر من هيك (ملايين) بدّه جداول حقيقية لكل نوع بدل JSON، وقراءة من نسخ، وعامل شغل لحاله: هاي الموجة 10، وبس إذا في زبون حقيقي بدّه.

**الأمان من الأول:** خاص إلا إذا انفتح، الحظر مطلق، كل بلاغ إله طابور، العضو بينزّل بياناته وبيمسح حسابه، والقاصرين بإعدادات أشدّ.

## سيرفرات الألعاب بالتفصيل (FiveM، ماينكرافت، وغيرهم)

طلبها المالك بـ 2026-11-22. موقع السيرفر غير عن باقي المواقع: اللي بيفوت عليه **لاعب**، وبدّه يعرف بسرعة: السيرفر شغّال؟ قدّيش في ناس؟ كيف بفوت؟ وين الديسكورد؟ شو القوانين؟ كيف بقدّم عالوايتلست؟

**النموذج الجديد «سيرفر»** (رقم 14): الصفحة الأولى بتبلّش بحالة السيرفر الحيّة وكبسة «فوت هلّق» والديسكورد، مش بصورة كبيرة وكلام.

**الصفحات:** الرئيسية (الحالة، فوت هلّق، ديسكورد، آخر تحديث، الفعالية الجاية)، القوانين، التقديم (وايتلست ووظائف)، الباقات، التحديثات، الفريق، الترتيب، الفعاليات، دليل اللاعب الجديد، الاستئناف والبلاغ، وحسابي (طلباتي، مشترياتي، أرقامي).

**الوحدات الجديدة:**

**«إستبرق لينك»: قطعة صغيرة بتنزل على سيرفر اللعبة.** resource لـ FiveM (Lua) و plugin لماينكرافت (Paper/Spigot، Java)، وبعدين Rust (Oxide). هي اللي بتحكي مع الموقع، مش الموقع اللي بيفوت عالسيرفر: ما في منفذ بينفتح، ولا كلمة سر RCON بتطلع برّا. شغلها:
- **الوايتلست:** لما حدا بيفوت، بتسأل الموقع إذا هو مقبول (بـ FiveM عن طريق الـ deferrals).
- **ربط الحساب** بالكود.
- **الأرقام** للترتيب كل كم دقيقة.
- **تسليم المشتريات، بماينكرافت بس:** بتسحب «شو لازم ينعطى»، بتشغّل الأمر (`lp user {player} parent add vip`)، وبتعلّم إنه انعطى.
- بتنبني وبتنختم لكل موقع متل الـ launcher (#227)، وبتنزل من لوحة الموقع مع مفتاحها.

**البيع حسب قواعد كل لعبة (هاي مهمة):**
- **FiveM:** حسب وثائق Cfx.re، Tebex هو شريك البيع الحصري لسيرفرات FiveM. يعني نحنا ما منقبض ولا منحط Stripe. موقعنا بيعرض باقات Tebex تبع السيرفر (Tebex Headless API بالتوكن العام) بشكل الثيم، والدفع والتسليم جوّا اللعبة عند Tebex.
- **ماينكرافت:** قواعد Mojang التجارية بتمنع بيع شي بيعطي أفضلية تنافسية باللعب. الأشكال والألقاب والمؤثّرات اللي ما بتأثّر عاللعب مسموحة. كل باقة فيها سؤال «بتعطي أفضلية؟»، وإذا الجواب نعم ما بتنتشر لسيرفر ماينكرافت، وبيطلع كلام بيشرح ليش. وبالذيل لحاله سطر «مش منتج رسمي لماينكرافت، ومش تابع لـ Mojang أو Microsoft».
- **ألعاب تانية (Rust، GMod، ARK…):** كل لعبة إلها قواعدها. المتجر ما بيفتح للعبة لحد ما نقرأ قواعدها ونحطها بالبوابة.
- **سكربتات FiveM و MLO:** الملفات المحمية (escrow) بتنباع عن طريق Tebex كمان. بلجنات وخرايط ماينكرافت منبيعها نحنا بالمفاتيح والرخص الموجودين عنّا.
- نحنا مش محامين: كل قاعدة إلها رابط لمصدرها باللوحة، وإذا اتغيّرت القواعد بتتغيّر البوابة معها.

**لوحتها:** الحالة ورسم اللاعبين ورسالة بالديسكورد إذا طفى السيرفر، طابور التقديم بالتصويت، الاستئنافات والبلاغات، المشتريات (بماينكرافت: انعطت، بتستنّى، فشلت مع «جرّب كمان مرّة»)، الفريق ومين مناوب، محرّر القوانين، كاتب التحديث (بينبعت للديسكورد)، الفعاليات، و«إستبرق لينك» (نزّلها، مفتاحها، آخر مرّة حكت).

**إعداداتها:** اللعبة، عنوان السيرفر أو كود cfx.re، رابط الديسكورد ورقمه، توكن Tebex العام، الوايتلست شغّال؟، أسئلة التقديم، كم يوم قبل إعادة التقديم، أقل عمر، روابط التصويت والخريطة، ولغة السيرفر.

**الثيمات:** عيلة «سيرفرات ألعاب» فيها 6 ثيمات أصلية: ليل نيون، بكسل مربّع (رسم من عنّا، مش بلوكات ماينكرافت ولا خطّه)، سرفايفل خشن، سباق بخطوط، إي-سبورت نظيف، وغيلد فانتازيا. ولا لوغو ولا رسمة ولا خط من الألعاب نفسها، وأسماء الألعاب بس بالكلام («لسيرفرات ماينكرافت Java»).

**بصراحة:**
- نحنا منعمل **الموقع**، مش سيرفر اللعبة. استضافة اللعبة بتضل عند المالك (أو عند شركة استضافة).
- قراءة الحالة بدها اتصال TCP و UDP من السيرفر تبعنا لسيرفر اللعبة: لازم نجرّبها على Railway قبل ما نوعد فيها.
- بنقبل بس عناوين عامة (مش شبكة داخلية)، ومع حدّ لعدد الأسئلة: عشان ما يصير الموقع أداة لضرب سيرفرات حدا.
- ما في مضادّ غش، ولا بيع حسابات، ولا boosting.

### الموجة G: سيرفرات الألعاب (6 PRs)
اقتراحي إنها تيجي بعد الموجة 1 مباشرة (بدها إعدادات الموقع ولوحته)، وقبل الثيمات.

- **انبنى:** G1 (2026-11-22): النموذج «سيرفر» (رقم 14) والمجال «سيرفرات ألعاب»، وقارئ الحالة لأربع ألعاب: FiveM (معلوماته بـ HTTP أو بكود cfx.re)، ماينكرافت Java (Server List Ping بـ TCP)، Bedrock (ping بـ UDP)، وألعاب Steam (A2S مع الـ challenge). السيرفر تبعنا بيسأل كل دقيقة (مهمة «حالة سيرفرات الألعاب») وبيحفظ يومين (جدول GameSample)، وبيرفض أي عنوان بشبكة داخلية أو محلية. عنصر صفحة جديد «حالة السيرفر»: شغّال أو طافي، كم لاعب من كم، الاسم والخريطة، رسم آخر 24 ساعة، و«فوت هلّق» بيفتح اللعبة (fivem://، steam://، أو رابط cfx.re) أو «انسخ العنوان» لماينكرافت، وبيسأل كل دقيقة. السيرفر بيعبّيه وهو بيبعت الصفحة. باللوحة قطعة «السيرفر هلّق» مع «اسأل هلّق» (مرّة كل 10 ثواني). كبسة الديسكورد بتاخد رابطها من إعداد. أول موقع: سيرفر رول بلاي FiveM «مدينة الندى» (حالة، كيف تفوت، تحديثات، طاقم، أسئلة، ديسكورد، تواصل). ما انجرّب على Railway لسّا: لازم نتأكد إنه بيقدر يحكي TCP و UDP لبرّا.
- **انبنى:** نص G2 (2026-11-22): **الدخول بحساب Discord**: كبسة «ادخل بحساب Discord» بصفحة «حسابي»، بتروح على Discord وبترجع على عنوان المتجر نفسه، والسيرفر تبعنا بيبدّل الكود بمين اللاعب بالسر DISCORD_CLIENT_SECRET (بالاتصالات والأسرار). بيفتح حساب بس بإيميل Discord أكّده، واللي عنده حساب بنفس الإيميل بيفوت على نفس الحساب. والدخول بيكمل بس بنفس المتصفح اللي بلّش منه. **ربط Steam**: Steam ما بيعطي إيميل، فاللاعب بيربطه من «حسابي» بعد ما يفوت، وجواب Steam بينسأل عنه Steam نفسه قبل ما نصدّقه، وحساب Steam واحد لكل حساب. بيطلع بحساب اللاعب «حسابات اللعب» (Discord مربوط، رقم Steam، فك الربط). **عدد الأونلاين بالديسكورد** تحت حالة السيرفر («342 هلّق على الديسكورد من 2,187») من رابط الدعوة، بينسأل مرّة كل 5 دقايق. المالك بيشغّلهم من الزبائن ← «الدخول بحساب Discord وربط Steam»، والكرت بيقلّه شو يعمل بـ Discord وشو العنوان اللي لازم يحطّه هناك. ما انجرّب مع Discord و Steam الحقيقيين لسّا: بالتجارب لعبنا دورهم. الباقي من G2: «اتصال جاهز» ديسكورد (رسالة بقناة، تعطي رتبة وتشيلها).
- **انبنى:** باقي G2 (2026-11-22) = G2 خلصت: **ديسكورد «اتصال جاهز»** بالاتصالات والأسرار، متل تلغرام و Slack: توكن البوت بينحفظ مرّة وما بيرجع، ورقم السيرفر والقناة المعتادة. بيعمل تلات شغلات بالـ functions: «ابعت رسالة بقناة» (والمنشن اللي بالكلام بيضل كلام: ما حدا بينعمله ping من شي كتبه زبون)، «أعطي رتبة» و«شيل رتبة». التوكن بيروح بس لـ discord.com. والـ functions صارت بتعرف حسابات اللاعب: {{caller.discordId}} و{{caller.steamId}} للي طلبها، وخطوة «زبون» (اقرأ) بتعطي discordId و steamId لأي زبون، فمثلاً لما ينقبل طلب وايتلست: اقرأ صاحب الطلب ← أعطي رتبة لـ {{player.discordId}}. ما انجرّب مع بوت ديسكورد حقيقي لسّا.
- **انبنى:** نص G3 (2026-11-23): **القوانين والتقديم**. صفحة «القوانين» بأقسام مرقّمة (1.1، 2.3) من جدول بيعدّله المالك، وفوقها «آخر تعديل» وشو تغيّر (إعداد). صفحة «التقديم» فيها الأدوار (شرطة، إسعاف، ميكانيك، طاقم الإدارة)، كل دور بشروطه وصفحته وفورمه وسؤاله الخاص، واللاعب بيوافق عالقوانين وهو بيقدّم. الطلب بينكتب باسم اللاعب (لازم يفوت، بحساب Discord مثلاً)، وبيقرا طلباته بـ «طلباتي» مع رد الطاقم، بس ما بيقدر يكتب حالة الطلب ولا الرد (حقول «مقفولة» جديدة بالجدول)، وملاحظات الطاقم ما بتوصله. طول ما طلبه عم ينراجع ما بيقدّم مرّة تانية على نفس الدور، وبعد الرد بيستنّى أيام بيحددها المالك (قاعدة جديدة بملف الموقع)، والسبب بينقاله تحت الكبسة. باللوحة: طابور «طلبات التقديم» فيه مين قدّم (اسمه، إيميله، Discord و Steam)، **وكل واحد من الطاقم بيصوّت مرّة** («مع» أو «ضد» مع ملاحظة، وبيغيّره أو بيشيله)، و«اقبل» بتستنّى عدد أصوات «مع» اللي بيحدده المالك. ولوح «الطلبات» حسب الحالة، والقوائم والتقارير. لما ينقبل: سطر بجدول الوايتلست وإيميل للاعب (وللمقابلة والرفض إيميل كمان)، و function ديسكورد بتعطي رتبة الدور وبتخبّر قناة الطاقم بكل طلب جديد (بتشتغل لما يختار المالك اتصال ديسكورد وينشرها). فورم لجدول صار فيه يبعت قيم ثابتة مع اللي انكتب (متل الدور). الباقي من G3: الاستئناف والبلاغ.
- **انبنى:** باقي G3 (2026-11-23) = G3 خلصت: **الاستئناف والبلاغ** بصفحة وحدة. الاستئناف على باند برقمه، ولكل باند استئناف واحد مهما مين بعته (والسبب بكلام المالك لما ينبعت مرّة تانية). البلاغ على لاعب: شو عمل (سبب من قائمة)، إمتى، شو صار، رابط كليب، وصورة بيرفعها اللاعب وبتضل خاصة (بيفتحها الطاقم واللي بعتها بس). بلاغ تاني من نفس اللاعب على نفس اللاعب بيستنّى لحد ما ينرد عالأول، مهما انكتب الاسم. تحت الفورمين «اللي بعتّه» مع الحالة ورد الطاقم. باللوحة طابور لكل واحد (شيل الباند أو خلّيه؛ انعمل إجراء أو لأ)، وأرقام، وقوائم، ورسم وتقرير للبلاغات حسب السبب، ولما ينقرّر بيوصل اللاعب إيميل فيه رد الطاقم. صار القالب ياخد لحد 24 صفحة (موقع السيرفر صار 11). وأسماء حقول الجداول صارت بتحكي عن اللاعب متل ما بيقراها الطاقم («اسم الشخصية»)، والفورمات بتضل تحكي مع اللاعب.
- **انبنى:** نص G4 (2026-11-23): **باقات Tebex لـ FiveM** (القرار 7 متل ما هو مقترح: البيع عن طريق حساب Tebex تبع صاحب السيرفر). صفحة «الباقات» بتعرض باقات متجر Tebex تبعه بشكل الموقع: أقسام كتبويبات، وكل باقة بسعرها (والسعر قبل الخصم إذا في)، وكلمتين عنها، وكبسة «اشتري عند Tebex» بتفتح الباقة بمتجره عند Tebex، وهناك بيفوت اللاعب وبيدفع وبيستلم. السيرفر تبعنا بيقرا المتجر من Tebex Headless API بالـ Public Token بس (إعداد بيضل عالسيرفر، المتجر ما بيشوفه)، كل 5 دقايق، والكلام بيوصل بدون HTML. موقعنا ما بيقبض ولا بيشوف بطاقة حدا. باللوحة قطعة «متجر Tebex»: متصل ولّا لأ، وكم باقة بكم قسم، أو ليش ما زبط. صفحة الباقة عند Tebex (`/package/<id>`) هي عنوان صفحة الباقة بمتاجر Tebex، بس وثائق الـ Headless ما ذكرته: لازم نتأكد منه مع متجر حقيقي. الباقي من G4: متجرنا لماينكرافت مع بوابة «بتعطي أفضلية؟».

  - **316 كلان «نسور الليل»:** الديسكورد، التشكيلة، المباريات والنتايج، «انضم للنسور» بتصويت الطاقم (الفورم بيسأل عن اسمك باللعب وخبرتك، مش عن شخصية)، القوانين والأخبار. ثيمه «غيلد فانتازيا».
- **انبنى:** G7c2 (2026-11-23): **«دوّر على فريق» والستريمر** (صاروا 28 موقع، 16 منهم للاعبين) = G7c خلصت:
  - **قارئ الحالة بيقرأ كمان قناة Twitch:** لايف ولا لأ، كم واحد عم يتفرّج، عنوان البث ولعبته، بمفاتيح Twitch تبع الموقع نفسه (وبلاها ما منسأل ولا منحفظ شي). البطاقة بتحكي «لايف هلّق» و«عم يتفرّجوا» أو «مش لايف هلّق»، وكبستها «شوف البث».
  - **وحدة «دوّر على فريق»:** اللاعب الفايت بحسابه بيحط طلب (اللعبة، النمط، رتبته، جهازه، منطقته، إمتى، والمايك، واسمه عالديسكورد) وبيطلع عاللوحة على طول (طلبات الزباين بتوصل مسودّة، فوظيفة بتنشرها). اللوحة قسم لكل لعبة، بتنقرأ بمتصفّح اللاعب وبتتحدّث لحالها لما يجي طلب، وكبسة «انسخ اسمه» بتنسخ اسم الديسكورد. الطلب بيسكّر لحاله بعد وقته (3 ساعات لـ «هلّق»، 8 لـ «الليلة»، 3 أيام لـ «الويكند»: خطوة كود كل ربع ساعة)، وطلب مفتوح واحد لكل لاعب، والطاقم بيسكّر أي طلب من اللوحة.
  - **وحدات الستريمر:** «جدول البث» (أيام الأسبوع وساعاتها وشو فيه)، «الكليبات» (صورة ورابط Twitch أو يوتيوب، الأحدث أول)، و«الرعاة» (لوغو ورابط وكود خصم للمتابعين). وسيرفره من وحدة «السيرفرات» بحالته وعنوانه.
  - **317 «لاقي فريقك»:** اللوحة بأربع ألعاب، الديسكورد بأونلاينه، قوانين (بلا بيع حسابات ولا «بوستينغ»). ثيمه «إي-سبورت نظيف».
  - **318 «ليث يلعب»:** لايف هلّق من Twitch، سيرفر المتابعين، جدول البث، الكليبات، الرعاة، الديسكورد. ثيمه «ليل نيون».
  - **الباقي (4):** G7d الشغل (304 استوديو سكربتات FiveM، 309 استوديو بلجنات ماينكرافت، 319 استضافة سيرفرات، 320 قائمة سيرفرات).
