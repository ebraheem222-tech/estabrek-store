# Estabrek Rose Storefront

Arabic-first pink design for hijabs, dresses and modest clothing. The opening campaign shrinks with scroll. The procedural Three.js hijab has its own section after the first product section, with manual rotation and color controls. Explicit product or 3D color selection coordinates the whole theme: tinted surfaces, readable text, buttons, filters, footer and navbar. Home and Shop keep the selected palette while scrolling, and scroll never resets the chosen cloth color. About and Contact retain their scroll palettes. The last colour a shopper picks is saved in the browser and restored on every page except About, which keeps its own scroll palettes. Campaign images are editorial inspiration; products, prices and availability come from the catalog.

From PowerShell:

```powershell
cd C:\Users\Ibrah\Desktop\estabrek\estabrek-storefront
npm.cmd install
npm.cmd run dev
```

Configure API_BASE_URL and NEXT_PUBLIC_API_BASE_URL in .env.local; see .env.example. Open http://localhost:3000. For a production preview, run `npm.cmd run build` followed by `npm.cmd run start`.

The published CMS homepage controls content, section order and visibility. Simple Hero, product, collection, FAQ and CTA sections receive the rose presentation. Composed components, slides, custom row/grid layouts and unsupported sections keep the original renderer. When no homepage is published, the rose fallback reads the catalog. cmsOverrideHome=false selects the fallback. ESTABREK_HOME_MODE=cms restores the original shell and CMS presentation.

In Admin → Pages → homepage → first Hero, open استبرق — الصفحة الوردية وتجربة الأقمشة 3D. Edit the campaign title/image/alt, three story words, 3D visibility and default video visibility. Existing Hero subtitle and buttons still apply. If the previous Hero image is the site logo, the default hijab campaign is used. Each section also has optional rose palette and motion intensity controls. Native style controls and Admin inline previews use the original renderer; the storefront shows the rose presentation.

The real 11-second fabric video uses a 245KB mobile source and 824KB desktop source, a poster and visible play/pause control. Published MP4 VIDEO sections replace the default clip and retain their order. Composed video blocks and other providers retain the native renderer. Reduced motion and disabled CMS animation use manual video playback.

Shop uses a compact campaign, larger 3:4 garment cards and category pills. Existing category/color/size/price/stock filters, URL history, sort and pagination are retained. Desktop filters have a scrollable sidebar; phones and tablets use a focus-trapped drawer animated with GSAP. Cards reveal once with GSAP rather than updating their colors on each scroll frame. Contact preserves authored channels, form field names and native composed sections and posts to the existing contact service. About uses authored content when published, otherwise the public store description and factual brand copy. The same legacy-mode switch applies to all four routes.

The language switch translates interface text; CMS-authored text remains in its authored language. Reduced-motion and the CMS animation switch show a static opening and all three fabric chapters without long sticky spacing. Every chapter is also rendered without JavaScript. WebGL failure shows a matching hijab illustration. The standalone canvas loads near its own section and pauses offscreen. Native CMS template libraries use separate bundles while retaining server-rendered content.

Validation: npm run typecheck, npm run build, npm test. Browser tests use installed Google Chrome and an isolated catalog/CMS fixture. Stop live-data manual previews before testing. Admin controls: `npm.cmd test -- src/features/pages/RoseHeroSettings.test.tsx src/features/pages/RosePresentationSettings.test.tsx --maxWorkers=1 --pool=threads` from estabrek-admin.

See public/editorial/README.md for image prompts and font licenses. Real product GLB viewers still use their existing configuration.

## Polish pass

- **Seasonal scene (home):** a pinned section after the collections grid. Scrolling holds the page while it changes from winter (rain, snow, 3D ice crystals, deep plum knit on the 3D dress form) to spring (rising sun, 3D blossoms and petals, blush silk). The storefront theme follows the season and returns afterwards. Products come from the categories whose slug or name matches winter/شتو and spring/ربيع (falling back to summer/صيف); with neither category the scene is hidden. Hide it from Admin by setting `roseSeasonsEnabled: false` on the first Hero. Reduced motion or disabled CMS animation shows both seasons as static blocks; WebGL failure keeps the CSS snow/sun.
- **Product imagery:** every product photo sits in a 4:5 frame on one beige backdrop (`--frame-bg` in `cinematic.css`). A second product image fades in on hover. Badges: «جديد» for products added in the last 30 days, «الكمية محدودة» at 5 pieces or fewer (`src/lib/productBadges.ts`).
- **Trust:** trust bar under the hero, size guide on the product page (edit `SIZE_GUIDE_ROWS` in `src/components/SizeGuide.tsx`), store-policy FAQ entries appended when the CMS FAQ lacks them (`src/components/cinematic/roseCopy.ts`), a Testimonials section rendered in the rose style when published in Admin, otherwise an Instagram invitation.
- **Copy guard:** `roseCopy.ts` upgrades a few early placeholder strings (hero buttons, generic taglines, masculine help text, Latin “?”) at render time. Editing the text in Admin takes precedence.
- **Type:** headings use Cairo (Rose Arabic); body text uses IBM Plex Sans Arabic (`public/fonts/plex-arabic-*.woff2`, OFL).
- **Chrome:** one floating action (WhatsApp); the accessibility button sits small on the opposite corner; no scroll line or floating back-to-top on the rose storefront. Reveals are 0.4s and start 160px before an element enters the viewport; smooth `scroll-behavior` is off.
- **Campaign clip:** with motion allowed the clip is played by the scroll (forwards and backwards) while the section holds; the arch opens into a wide frame and a small timeline shows the position. No pause button is needed because the shopper controls the motion; reduced motion or CMS animations off keep a poster with play/pause. WebM versions (`rose-campaign*.webm`) sit beside the MP4s, all encoded with a keyframe every 8 frames for smooth seeking.
- **Seasons placement:** the winter → spring scene now sits directly above the first products section («وصل حديثاً»).
- **Collection hover:** hovering (or focusing) a collection card dresses the storefront in that collection's colour: Admin `themeColor` on the item, else a known collection (winter, summer, kids, accessories, incense, hijab, dresses…), else a colour sampled from its photo. Leaving the grid returns to the previous colours.
- **Smooth colour changes:** swatch picks, collection hovers and the seasonal scene animate the theme with GSAP (`src/lib/themeTween.ts`); a colour carried over from the previous page is applied instantly.
- **Collection worlds (home):** a second pinned scene after the collections grid. Scrolling moves through accessories → kids → incense, each with its own procedural 3D model (smart tasbih ring with pearl orbit and shawl pin; floral girl's dress with puff sleeves and a bow; carved wooden mabkhara with gold inlay, glowing bakhoor and rising smoke), backdrop, four products and storefront colour, then the colours return. Categories are matched by slug/name (accessories/إكسسوار, kids/أطفال, incense/مباخر); missing ones are skipped. Hide it from Admin with `roseStoriesEnabled: false` on the first Hero.
- **Bag (/cart):** rose bag with photos, colour/size chips, quantity steps, coupon, delivery details (name and phone required) and a three-step indicator. Orders are recorded in the store first (`/catalog/order-requests`), then WhatsApp opens with the order number and the full list ready to send. Stripe/PayPal buttons appear when those checkout modes are enabled. Local WhatsApp numbers such as `0544204029` are converted to international form for wa.me (`src/lib/whatsapp.ts`, by the store country, default Israel +972).
- **Wishlist and search:** /wishlist shows saved pieces as rounded 4:5 cards; /search has a large search field with the result count above the rose shop grid and filters. A CMS page published at /cart or /search still takes precedence.
- **Add-to-bag colour play:** while the pointer rests on any add-to-bag button the storefront takes a new random colour every second (`startThemeCycle` in `src/lib/themePreview.ts`); leaving glides back. Touch screens skip it.
- **Colour hand-back:** the seasons scene, the collection worlds and hover previews share one record of the page's resting colours (`src/lib/themeBase.ts`), and the shopper's chosen colour always wins, so scrolling quickly through the scenes and back to the top returns to her colour.
- **Product photos:** clicking the main photo (or Enter) opens a full-screen viewer with arrows, thumbnails, swipe, keyboard and click-to-zoom (`RoseImageViewer.tsx`); hovering the photo still zooms in place.
- **Speed:** the homepage starts its scene data (categories, seasons, collection worlds) together with the page instead of after the other product requests, and the product page fetches settings, categories and related pieces in parallel. `npm run dev` compiles each page on first visit, so it feels slow; `preview-storefront.bat` (in the estabrek folder) builds and runs the optimized site.
- **Quick view and quick add:** on the rose storefront both open a sheet in the campaign design (`RoseProductSheet.tsx`) with the product photo of the chosen colour, colour circles, sizes, quantity and add-to-bag; light list products are completed from the API when photos or sizes are missing. The custom cursor theme from Admin is ignored here, so the normal cursor shows.
